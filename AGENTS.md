# Viața Părintelui Cleopa · Școala Evlaviei

**Blender creează actorii, decorurile și repertoriul de gesturi. JavaScript regizează filmul. Three.js îl animează și îl randează.**
Un episod este `episodes/<id>/episode.json` (regia) + pista audio, peste GLB-urile reutilizabile din `assets/` ([contractul](assets/CONTRACT.md)). Motorul e în `lib/engine/` ([documentația](docs/ENGINE.md), [descriptorul](docs/EPISODE.md)). Pagina principală (`/?ep=<id>`) redă toate episoadele cu playerul Three.js. Playerul, cadrele de verificare și exportul CLI folosesc același motor și aceeași funcție `stage.setTime(t)`.

Pentru un episod, folosește [skill-ul `facut-episod`](.agents/skills/facut-episod/SKILL.md). Pentru probe GPU, folosește [skill-ul `render-runpod`](.agents/skills/render-runpod/SKILL.md). Pe RunPod rulează orice probă care ar dura **peste 3 minute** pe CPU-ul containerului și se poate accelera pe GPU când `RUNPOD_KEY` este disponibilă (randări de probă, foi de cadre, verificări pe cadre randate) — vezi „Când folosim RunPod” din skill. Pentru scenele Blender ale familiei, citește și [instrucțiunile proiectului original](experiments/cleopa-blender/AGENTS.md).

- Un episod nou se scrie ca descriptor în `episodes/<NNN-slug>/episode.json`, cu distribuția, planurile, gesturile (`do`) și recuzita. Nu scrie scripturi Python per episod, nu exporta din Blender scena unui episod și nu precalcula transformările sau deformările filmului (`assets/film/plan-*` e doar referința veche).
- Blender (`blender/`) construiește numai asset-uri reutilizabile: personaje, decoruri, recuzită, variante. Un gest nou intră în `lib/engine/gestures.js`, nu într-un reexport. Dă nume stabile personajelor, gesturilor, obiectelor și planurilor. Refolosește biblioteca înainte să modelezi o variantă nouă; o variantă e un nod marcat în același GLB.
- Experimentele și scenele Blender vechi rămân în `experiments/<episod>/` ca referință vizuală.
- Spune povestea cu replici scurte și română firească. Populează fiecare plan cu acțiunea cerută de replică. Verifică orientarea personajelor, traiectoria obiectelor și continuitatea dintre cadre. Folosește culorile calde și siluetele clare ale seriei.
- Pentru decorurile ilustrate din `Micuțul Cleopa`, folosește cadrul 2, „Ograda în zori”, ca referință pentru stil, compoziție și separarea planurilor. Urmează [ghidul de ilustrație](experiments/cleopa-painea/assets/backgrounds/README.md).
- În Blender, pornește cu `bpy` și `--python-exit-code 1`. Verifică umărul, cotul și manșeta în gest și în repaus. Brațul relaxat se oprește clar deasupra genunchiului. Fixează punctele de sprijin și ajustează adâncimea întregului personaj înainte să schimbi adâncimea unei mâini. Motivează orice suprapunere intenționată (`episodes/<id>/allow.json`, cu interval și motiv).
- Păstrează paritatea motorului cu Blender: `npm test` compară FK-ul, IK-ul brațelor și palmele C cu Python (1e-6). O schimbare în `palme25d.py` se face și în `lib/engine/palm25d.js` și în atelierul `/palme/`.
- Pentru semnul crucii, palma dreaptă merge la frunte, piept, umărul drept și apoi la stângul personajului. Verifică fiecare contact și înclinarea de la final în camera activă.
- Păstrează pista românească și muzica separate la editare. Folosește cheia OpenRouter din mediu. Păstrează filmul curent fără subtitluri. Aplică sigla Școala Evlaviei din `assets/branding/` la preview și la materiale, conform cerinței episodului.
- Pentru a vedea cadre în timpul lucrului, folosește `npm run stills -- <episod> <cadre>` (motorul, secunde). `npm run check:engine -- <episod>` verifică mâinile peste capete, smuciturile, încadrarea vorbitorului, gura în replici și determinismul după salturi. `npm run compare` pune motorul lângă o referință, plan cu plan.
- Înainte de push, rulează `npm test`, `npm run build` și `npm run check:engine` pentru episodul schimbat. Verifică redarea, derularea și notele în preview-ul local (`npm run check:preview`, `node tools/engine/motor-check.mjs <adresă> <episod>`). Generează MP4 numai când utilizatorul îl cere explicit, cu `npm run export:mp4 -- <episod>`. Predă fișierul separat de site. Buildul, preview-ul și verificările lucrează cu descriptorul, nu cu MP4-ul. Păstrează cheile și fișierele de feedback în afara Git.
- Pentru fiecare revizie, publică schimbările pe un branch și deschide un pull request. Trimite utilizatorului linkul la PR și la deploymentul Vercel Preview al branch-ului imediat ce URL-ul este disponibil, chiar dacă buildul încă rulează.
